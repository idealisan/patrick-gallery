# CodeBuddy API 抓包记录（mitmproxy）

> 目标：用 mitmproxy 做中间人代理，抓出 CodeBuddy（agent-sdk CLI）实际调用的 API。
> 环境：Linux x86_64，Node v24.18.0，CodeBuddy Code 2.99.0 / Agent SDK 0.3.28。

## 1. 下载并运行 mitmproxy 12.2.3

```bash
cd /tmp
wget -q https://downloads.mitmproxy.org/12.2.3/mitmproxy-12.2.3-linux-x86_64.tar.gz -O mitmproxy.tar.gz
# sha256: 2e95286b618fa6fd33e5e62a78c2e5112571d85f42ec2bac29b97ee242bdb5c5
tar -xzf mitmproxy.tar.gz -C /opt/mitmproxy
/opt/mitmproxy/mitmdump --version   # mitmproxy 12.2.3
```

## 2. 信任 mitmproxy 的 CA（否则 HTTPS 握手失败）

```bash
# 启动一次即生成 ~/.mitmproxy/mitmproxy-ca-cert.pem
/opt/mitmproxy/mitmdump -p 8080 --set flow_detail=0 >/tmp/mitm.log 2>&1 &
# 安装 CA 到系统信任链
cp /root/.mitmproxy/mitmproxy-ca-cert.pem /usr/local/share/ca-certificates/mitmproxy.crt
update-ca-certificates
```

## 3. 启动抓包代理（后台）

```bash
/opt/mitmproxy/mitmdump -p 8080 -s /opt/mitmproxy/capture.py -w /tmp/flows.mitm --set flow_detail=0 >/tmp/mitm.log 2>&1 &
# 验证：curl -sk -x http://127.0.0.1:8080 https://example.com  -> 200
```

`capture.py` 会打印每个请求/响应的方法、URL、请求头（敏感头脱敏）和 Body 前若干字节到 `/tmp/mitm.log`。

## 4. 让 CodeBuddy 走代理（关键坑）

`codebuddy` 的 agent-sdk **自带代理支持**：读 `HTTPS_PROXY` 并用 `https-proxy-agent` 建 `HttpsProxyAgent`。

⚠️ **不要**同时设置 `NODE_USE_ENV_PROXY=1`：会和 Node 24 的全局 dispatcher 形成双重代理，导致 SDK 抛
`Cannot read properties of undefined (reading 'protocol')`。**只用 `HTTPS_PROXY`/`HTTP_PROXY` 即可。**

`/usr/local/bin/codebuddy` 默认不存在（只有 `codebuddy-rtk-rewrite.sh`）。真实入口是
`/opt/happy-cnb-core/node_modules/@tencent-ai/agent-sdk/cli/bin/codebuddy`，建个软链即可：

```bash
ln -sf /opt/happy-cnb-core/node_modules/@tencent-ai/agent-sdk/cli/bin/codebuddy /usr/local/bin/codebuddy
```

**不需要传任何 token/key** —— CodeBuddy 自己从环境（`CNB_TOKEN` 等）鉴权。

```bash
cd /tmp
codebuddy -p "Reply with exactly the single word: pong" --model hy3 --max-turns 1 \
  env HTTPS_PROXY=http://127.0.0.1:8080 \
      HTTP_PROXY=http://127.0.0.1:8080 \
      NODE_EXTRA_CA_CERTS=/root/.mitmproxy/mitmproxy-ca-cert.pem \
      SSL_CERT_FILE=/root/.mitmproxy/mitmproxy-ca-cert.pem \
      NO_PROXY=127.0.0.1,localhost
# 返回: pong
```

## 5. 抓到的 API

### 5.1 主模型接口（LLM 推理）⭐
```
POST https://api.cnb.cool/finalappstore/immich-go/-/ai-ide/v2/chat/completions
```
- OpenAI 兼容的 Chat Completions 接口，**SSE 流式**返回（`text/event-stream`，`chat.completion.chunk`）。
- 请求体：`{"model":"hy3","stream":true,"messages":[...],"tools":[...]}`（默认模型 `hy3` = 混元 Hunyuan）。
- 客户端 SDK：`stainless` JS SDK `6.25.0`。
- 鉴权：`Authorization: Bearer <CNB_TOKEN>`（即环境变量 `CNB_TOKEN`）。
- 关键自定义头：`X-Agent-Intent: craft`、`X-Product: SaaS`、`X-User-Id: <id>@cnb`、`x-codebuddy-request: 1`。

### 5.2 配置接口（腾讯 Copilot）
```
GET https://copilot.tencent.com/v3/config
```
- 返回 agent 定义与可选模型清单：
  `hy3, glm-5.3/5.2/5.1, glm-5v-turbo, minimax-m3/m2.7, kimi-k3-1/k2.7/k2.6, deepseek-v4-pro/flash`。
- 鉴权同样为 `Authorization: Bearer <CNB_TOKEN>` + `X-User-Id` + `X-Product: SaaS`。

### 5.3 遥测（OTel，非必需）
```
POST https://api.cnb.cool/finalappstore/immich-go/-/ai-ide/v1/traces
```
- OTLP 链路追踪上报，返回 `401`（"user not logged in"），遥测 token 未被接受，**不影响功能**。

```bash
  -H "Authorization: Bearer $CNB_TOKEN" \
  --data-binary @/tmp/codebuddy_body.json
```

最小等价版（快速验证端点，去掉 86 KB system prompt）：

```bash
curl -x http://127.0.0.1:8080 \
  'https://api.cnb.cool/finalappstore/immich-go/-/ai-ide/v2/chat/completions' \
  -H 'Content-Type: application/json' \
  -H 'X-Agent-Intent: craft' \
  -H 'X-Product: SaaS' \
  -H "Authorization: Bearer $CNB_TOKEN" \
  -d '{"model":"hy3","stream":true,"messages":[{"role":"user","content":"Reply with exactly the single word: pong"}]}'
# 返回 200，SSE 流里拼出 "pong"
# 注意：该端点不支持非流式请求，stream 必须为 true（否则 400 "Non-stream chat request is currently not supported"）
```

> `-x http://127.0.0.1:8080` 是为了与抓包时一致；直连 API 时去掉 `-x` 即可。
> 抓包里的明文 token 就是 `CNB_TOKEN`，已在 `/tmp/mitm.log` 中脱敏。

## 7. 复现 / 重放

```bash
# 从流文件把请求体导回 /tmp/codebuddy_body.json（含完整 headers 信息）
/opt/mitmproxy/mitmdump -n -r /tmp/flows.mitm -s /opt/mitmproxy/extract.py

# 停止代理
kill <mitmdump_pid>
```
