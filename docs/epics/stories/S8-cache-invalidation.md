# S8: 版本驱动的缓存失效重建

- **Epic**: [维护与自愈体系](../maintenance-self-healing.md) · WI-4
- **优先级**: P2 · **估算**: 1d · **状态**: 待开工（依赖 S7；force 依赖 S1）
- **依赖**: S7（+S1 组合使用）

## User Story

作为管理员，当程序升级引入某格式族的解码 breaking change 后，我希望系统自动
识别该格式族下版本不匹配的缓存，并（经我触发 force 或任务运行时）只重建这些
过期缓存——兼容的缓存一律不动。

## 验收标准

1. 失效判定：`缓存记录版本 != 当前格式族版本` → 视为待重建
2. 队列模式（无 force）：items() 在"缺失项"之外并入"版本不匹配项"
3. force 模式（S1）：全量重跑，重建后写入新版本号
4. servePreview / thumbnail 读取路径遇到版本不匹配的缓存文件：
   不直接信任，按需重生成后覆盖（防止旧图漏出）
5. 端到端场景测试：a) bump heic 版本 → 仅 HEIC 资产进入待重建集合；
   b) 重建完成后全部资产版本=当前；c) JPEG 缓存未被触碰（mtime/内容不变）
6. 发版流程文档化：在 docs/README.md 或 Epic 中记录「升级解码器时如何 bump」
   一句话指引

## Out of scope

- 自动 bump（决策为人工评估）→ 见 §5.3
